# 协议规格书 · YunMu YM-S1-BES

所有结论均经真机报文验证。参考实现见 `yunmu_ble_meter/protocol.py`，回归样本见 `tests/test_protocol.py`。

---

## 1. 设备身份

| 项 | 值 |
|---|---|
| 广播名 | `YUNM` + MAC 12 位十六进制**字节反序** |
| 例 | MAC `26:04:18:01:12:F4` → 名 `YUNMF41201180426` |
| 地址类型 | **Public**（非随机），App 直接用云端存的 MAC 连接 |
| 发现方式 | 仅上电后有限窗口内广播；连接一次或超时后停止 |

> 名字反序规则：`F4 12 01 18 04 26` 反序 → `F4 12 01 18 04 26` 的十六进制串
> 按 `[10:12][8:10][6:8][4:6][2:4][0:2]` 拼接，即 MAC 六字节倒序的 hex。

## 2. GATT 层

```
service  49535343-fe7d-4ae5-8fa9-9fafd205e455     (ISSC / Microchip 透传服务)
  notify  49535343-1e4d-4bd9-ba61-23c647249616    (properties: notify)
  write   49535343-8841-43f4-a8d4-ecbe34729bb3    (properties: write-without-response)
```

另有标准 GAP（`00001800`）与 GATT（`00001801`）服务，可忽略。

- MTU 默认 23 → 每次写 20 字节，包间 100 ms。
- 连接后**必须先 `StartNotify`（写 CCCD）并等待约 0.8 s**，之后才能发第一条命令；
  否则第一条会超时。这是实测踩到的坑。

## 3. 帧格式

```
偏移  长度  内容
 0     2    magic
 2     2    payload 长度（大端）
 4     n    payload
 4+n   2    CRC16（大端），范围 = payload
```

### 3.1 magic

| magic | 含义 |
|---|---|
| `EC ED` | V1 明文帧（**本设备实际使用**） |
| `CE DE` | V2（AES-ECB）/ V3（明文），本设备未使用 |
| `93 92` | V0（无密钥） |
| `F0 0F` | 注册/绑定帧，**不做 XOR**，CRC 参数由云端下发 |

### 3.2 整帧混淆

除 `F0 0F` 帧外，**整帧（含 magic、长度、CRC）逐字节 XOR**：

```
key = (mac[0] + mac[1] + ... + mac[5]) & 0xFF
```

本例：`0x26+0x04+0x18+0x01+0x12+0xF4 = 0x149` → `key = 0x49`

### 3.3 CRC16

反射算法（LSB-first），参数从 MAC 派生：

```
init = (mac[5] + mac[4] + 10)               & 0xFFFF     → 0x0110
poly = ((mac[5] + 11) << 8 | mac[4])        & 0xFFFF     → 0xFF12

t = init
for b in payload:
    t ^= b
    for _ in range(8):
        t = (t >> 1) ^ poly if t & 1 else t >> 1
```

> **陷阱**：XOR key 存在撞车。`0xA5 ^ 0x36 == 0x93`、`0xA4 ^ 0x36 == 0x92`，
> 即错误 key `0x36` 会把帧头误判成 `93 92`。**判帧必须以 CRC16 校验通过为准**。

## 4. 业务层（payload）

payload 本身**再加扰**：

```
plain = payload_byte ^ 0x2C
```

### 4.1 请求帧校验字节

请求 payload 的最后一字节：

```
checksum = sum(payload[0..n-2]) & 0xFF
```

**注意**：这是对**解扰后**的字节求和，且求和的最后一位就是校验位本身之前的所有字节。
实测读指令与响应帧均成立。

### 4.2 指令表

| 指令 | 解扰后 payload | 校验 | 说明 |
|---|---|---|---|
| 读实时数据 | `A4 AC A4` | `83 72`(外帧CRC) | 3 字节，请求体无内校验 |
| 设预警阈值 | `83 AA A4 <hi> <lo> AC 9E AC AC <tail>` | 见 §6 | 9 字节 |

**读指令完整线上帧**（直接可用）：

```
A5 A4 49 4A ED E5 ED CA 3B
```

### 4.3 阈值编码

```
wire   = ((hi << 8) | lo)
value  = wire ^ 0xACAC        ← 解码
wire   = value ^ 0xACAC        ← 编码
```

验证样本（5/5 命中）：

| 设定值 | 帧域 hi lo | 解出 |
|---|---|---|
| 1000 | `AF 44` | 1000 |
| 2000 | `AB 7C` | 2000 |
| 2100 | `A4 98` | 2100 |
| 3000 | `A7 14` | 3000 |
| 9999 | `8B A3` | 9999 |

> 上表是 **XOR 0x2C 之前的帧域字节**（即 `parse()` 得到的 payload）。
> 若在明文域运算，掩码等价为 `0x8080`：`8000 ^ 0x8080 = 0x0080`。

## 5. 响应帧

一个响应是单帧报文，payload 解扰（XOR 0x2C）后结构如下：

```
plain[0]        reply type   0x08 = 读数, 0x07 = 清零应答
plain[1]        data 长度
plain[2:2+n]    data
plain[2+n]      checksum = Σ(plain[0 : 2+n]) & 0xFF
```

### 5.1 字段（type = 0x08，读数据，n = 29）

| data 偏移 | 长度 | 语义 | 缩放 | 验证 |
|---|---|---|---|---|
| 0–6 | 7 | 保留（全 0） | — | 恒定 |
| 7–8 | 2 | **累计计数** | 见 §6 | 单调递增，清零归零 |
| 9 | 1 | 保留 | — | 0 |
| 10 | 1 | **有功功率** | ÷10 → W | 与 V×I×PF 自洽 |
| 11–12 | 2 | **电压** | ÷10 → V | 224.4~231.1 实测 |
| 13 | 1 | 保留 | — | 0 |
| 14 | 1 | **电流** | ÷1000 → A | 同上 |
| 15 | 1 | **功率因数** | ÷100 | 同上 |
| 16–17 | 2 | 阈值回显 | 大端，未异或 | `07 D0` = 2000 |
| 18–20 | 3 | 保留 | — | 恒定 |
| 21 | 1 | 常量 50 | — | 恒定 |
| 22–26 | 5 | 保留 | — | 恒定 |
| 27 | 1 | 常量 5 | — | 恒定 |
| 28 | 1 | checksum | — | 见上 |

### 5.2 字段自洽性

三个标定点验证 `V × I × PF ≈ P`：

| 状态 | V | I | PF | V×I×PF | p10/10 |
|---|---|---|---|---|---|
| 空载 | 230.4 | 0.000 | 0.00 | 0.00 | 0.0 |
| 小负载 | 230.5 | 0.033 | 0.22 | 1.67 | 1.7 |
| 小风扇 | 231.1 | 0.054 | 0.36 | 4.49 | 4.5 |

误差 < 0.05，来自设备内部整数运算后的独立量化。

### 5.3 清零应答（type = 0x07，n = 13）

```
data[0:6]  保留（全 0）
data[6:8]  清零时刻的累计计数   ← 注意与读数据的偏移差 1
data[8:13] 全 0
```

实测：`01 40` = 320，正是清零前的计数。**偏移差异是固件特性，不是解析错误。**

## 6. 配置帧尾字节（未定）

5 个样本：`1000→FE, 2000→92, 2100→0F, 3000→86, 9999→31`

已穷举排除：

- CRC8：poly 1–255 × init 0–255 × 正/反射 × 各种字节切片 —— 无解
- CRC16 高/低位、sum8、xor8、`~sum`、`-sum`
- 仿射 `a·v+b (mod 256)`
- BCD 数字和、半字节和
- CRC-8/ROHC（poly 0xE0, init 0xFF）

**结论**：不是阈值的确定性函数，最可能是**序号 / 会话标记 / 参数组标识**。

**工程建议**：修改阈值时**回放已抓到的完整帧**，而不是自行构造。已抓样本见 §3 表格。

## 5.4 每台设备专属的两个值（重要）

以下两项**由云端按设备下发**，无法从 MAC 推导，且厂家固件对错误值**静默丢弃**
（不回 ATT 错误、不发通知，表现为"设备没反应"）：

| 项 | 说明 | 已采集 |
|---|---|---|
| 读指令 payload | 3 字节，帧域内 | 见下表 |
| payload 去扰常量 | 响应 payload 逐字节 XOR 的值 | 见下表 |

payload 形态恒为 `[s, s^0x08, s]`（4/4 验证）。

| 设备 | BLE MAC | 读 payload | 去扰常量 | SN |
|---|---|---|---|---|
| 1 号机 | `26:04:18:01:12:F4` | `a4 ac a4` | `0x2C` | `KK01264I12F4` |
| 2 号机 | `26:01:15:04:2F:96` | `5a 52 5a` | `0x0D` | `KK04261F2F96` |
| 3 号机 | `26:04:18:01:03:11` | `d0 d8 d0` | `0x79` | `KK01264I0311` |
| 4 号机 | `26:04:18:01:03:16` | `b0 b8 b0` | 待采集 | — |

两值都**与 MAC 无确定关系**，不能推。去扰常量可用穷举反推：对回复 payload
尝试 0–255，取使 `plain[0]` 为已知应答类型且内校验和自洽的那个值。

**采集注意**：设备上电后需等待约 30 秒完成初始化，否则连得上但不回应；
断电后立即重连同样会静默。

> **易错点**：用错去扰常量时，**整帧 CRC 依然通过**（CRC 只覆盖帧域 payload），
> 只有逻辑字段变成乱码。因此不能靠 CRC 判断常量是否正确，必须校验
> `plain[0]` 是否为已知应答类型且 `plain[0:2+n]` 的内校验和自洽。

采集方法见 `tools/fake_meter/`：用 ESP32-S3 冒充该设备的 BLE 公有地址，
让小程序把云端下发的帧写过来，串口即可打印。

复位/改阈值等其它指令的 payload 同样按设备下发，尚未采集。

## 6.1 清零指令的实测边界

清零帧 `AB AE AD 52 A4` 会让设备回一个 `0x07` 应答，应答里带着请求时刻的计数：

```
→ A5 A4 49 4C E2 E7 E4 1B ED B1 58
← EC ED 00 10 …   plain = 07 0D … 01 40 … 5A   （01 40 = 320，即清零前计数）
```

**但回放这条帧之后，继续 `read()` 读到的计数并没有归零。** 多次实测（含连续观察 30 秒）计数保持不变。

而 App 自己的清零操作确实让界面显示变成了 0.00。两者差异说明：**BLE 帧只是通知设备，界面的归零还有云端参与**，或者设备把归零写入了另一处我们读不到的存储。

**结论**：不要把这条指令当作"已确认归零"。需要累计量时，用本地积分（`yunmu_energy_kwh`），不要依赖设备计数器。

## 7. 完整收发示例

### 7.1 读一次实时数据

```
→ A5 A4 49 4A ED E5 ED CA 3B
← A5 A4 49 69 6D 78 65 65 65 65 64 65 65 65 8F 65 48 6C 62 65     (20B)
← 53 41 62 B5 65 65 65 57 65 65 65 65 65 65 60 D0 ED 4D           (18B)
```

拼接 38 字节后：

```
EC ED 00 20 | <32B payload> | CRC
payload 解扰 → 08 1D 00 00 00 00 00 00 00 00 EA 00 2D 09 07 00 36 24 07 D0 …
               data[7:9] = 00 00   累计计数（此样本为清零后）
               data[10]  = 0x2D
               V = (09<<8|07)/10 = 231.1 V
               W = data[10]/10  = 4.5 W
               I = 0x36/1000    = 0.054 A
               PF= 0x24/100     = 0.36
               阈值 = 0x07D0    = 2000 W
```

### 7.2 设阈值 2000W

```
→ A5 A4 49 40 CA E3 E2 35 E5 D7 E5 E5 DB 71 6E
```

解扰 payload = `83 AA AB 7C AC 9E AC AC 92`
→ `((0xAB<<8)|0x7C) ^ 0xACAC = 0x07D0 = 2000` ✔
